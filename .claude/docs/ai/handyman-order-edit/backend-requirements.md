# Backend Requirements: Handyman Order Edit

## Context

Клиент должен иметь возможность редактировать активный заказ хэндимена — так же, как сейчас работает редактирование клининг-заказа. Экран редактирования открывается из экрана активного заказа. Изменения применяются к уже созданному заказу.

## Screens/Components

### HandymanOrderEditScreen

**Purpose**: Позволить клиенту изменить параметры заказа после его создания, пока мастер ещё не назначен (или назначен, но с ограничениями).

**Data I need to display**:
- Текущая дата и слот времени заказа
- Текущий адрес выполнения работ
- Список выбранных видов работ с возможностью изменить
- Текущее описание задачи (если было указано)

**Actions**:
- Изменить дату и/или слот → заказ обновляется, клиент видит новые дату/слот
- Изменить адрес → заказ обновляется с новым адресом
- Изменить список работ → пересчитывается стоимость, заказ обновляется
- Изменить описание задачи → заказ обновляется с новым текстом
- Сохранить → все изменения применяются, клиент возвращается на экран активного заказа с актуальными данными

**States to handle**:
- **Loading**: пока данные сохраняются
- **Error / Conflict**: если заказ уже взят мастером и некоторые поля нельзя менять — нужно сообщить об этом
- **Restricted**: если статус заказа не позволяет редактирование — показать пояснение

**Business rules affecting UI**:
- Когда мастер уже назначен (`assigned`), хотим показывать предупреждение и, возможно, ограничить редактируемые поля (например, только описание и работы, но не дату)
- Пересчёт стоимости при изменении списка работ — нужно ли показывать новую цену до сохранения?
