# Backend Requirements: Deep Linking (Telegram Mini App)

## Context

Клиентское приложение — Telegram Mini App (TMA). Telegram передаёт параметр запуска
через механизм `startapp`: когда бот отправляет кнопку со ссылкой вида
`t.me/<bot>/<app>?startapp=<value>`, приложение получает это значение и сразу
открывает нужный экран.

Это нужно чтобы бот мог отправлять уведомления с кнопкой «Открыть заказ» —
и пользователь попадал прямо на экран своего заказа, а не на главную.

---

## Поддерживаемые параметры (реализовано на фронте)

### Wizard-экраны (открываются мгновенно)

| Параметр `startapp` | Что открывается |
|---|---|
| `cleaning` | Мастер создания заказа на уборку |
| `handyman` | Мастер создания заказа на хэндимен |
| `chistomaty` | Экран чистоматов |

Эти ссылки не требуют ID — они просто открывают форму создания заказа.

### Активные заказы (открываются после загрузки данных)

| Параметр `startapp` | Что открывается |
|---|---|
| `cleaning_<id>` | Экран конкретного активного заказа на уборку |
| `handyman_<id>` | Экран конкретного активного заказа на хэндимен |

Где `<id>` — идентификатор заказа, который бэкенд уже знает.

**Поведение при ненайденном заказе**: если заказ с таким ID не найден среди
активных (завершён, отменён, или чужой) — приложение просто показывает главный
экран без ошибки.

---

## Что нужно от бэкенда

### Бот — при отправке уведомлений

Когда бот отправляет уведомление о событии по заказу (назначен исполнитель,
статус изменился, и т.д.), кнопка должна вести на соответствующий deep link.

**Формат ссылки:**
```
https://t.me/<bot_username>/<app_name>?startapp=cleaning_<order_id>
```

Бот уже знает `order_id` — достаточно подставить его в параметр.

### Бэкенд — при создании заказа

Если бэкенд генерирует ссылки для уведомлений самостоятельно (например, через
Redis events), нужно добавить в событие готовую ссылку или хотя бы `order_id`
и тип заказа (`cleaning` / `handyman`), чтобы бот мог собрать ссылку.
